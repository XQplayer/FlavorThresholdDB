# 科研数据章节渐进预加载设计

## 目标

让公网用户明确知道科研章节需要加载，并在核心检索完成后以低并发方式自动准备数据。保持按实体隔离、来源失败可重试和已成功数据不丢失，同时修正 FlavorDB2 空结果的状态语义。

## 交互

- 科研章节初始状态显示“点击章节加载 / Click to load chapter”。
- 未启动章节的按钮额外显示“加载数据 / Load data”操作提示。
- 章节开始请求后立即显示加载动画，以及“预计需要 5–15 秒；公共数据源响应时间可能不同”。
- 核心身份、FEMA 和 compound 请求完成后，按光谱、生化关系、活性与靶点、蛋白结构的顺序渐进预加载。
- 同一时间只启动一个后台章节。用户点击未启动章节时，该章节立即获得优先级。
- 后台失败不会阻塞后续章节；失败章节保留现有独立重试入口。

## 状态与缓存

- 工作台为每个化合物实体维护已启动章节集合和当前预加载游标。
- 四个科研章节在首次启动后保持挂载；切换章节只切换可见性，不销毁其请求状态。
- 同一实体内重复访问不重新请求。切换实体时清空挂载和调度状态，由科学组件已有的 request key、generation 和 AbortController 防止旧响应回填。
- 调度仅在核心检索不再 loading、实体已确定且浏览器空闲后开始；使用 `requestIdleCallback`，不支持时用短延迟回退。

## FlavorDB2 状态

- `found: false`、空实体列表且无请求错误时统一映射为 `no_data`，中文显示“无匹配数据”，英文显示“No matching data”。
- 网络或上游错误继续映射为 `failed`，不得与无匹配混淆。

## 可访问性

- 加载动画不作为唯一状态表达，同时提供文字和 `aria-live` 公告。
- 后台预加载不抢夺焦点。
- 点击章节仍立即切换到目标面板；加载提示在面板标题下方可见。
- `prefers-reduced-motion` 下停用旋转动画，保留静态图标和文字。

## 验收与测试

- 单元测试覆盖状态文案、FlavorDB2 空结果、渐进队列顺序、单并发、点击提权、实体切换和已访问章节不重复启动。
- E2E 覆盖核心完成后的后台顺序加载、点击未启动章节立即加载、5–15 秒提示、章节切换不重复请求以及 FlavorDB2 空结果文案。
