# FlavorThresholdDB 检索结果工作台重构设计

日期：2026-08-03

状态：设计已确认，等待用户审阅书面规范

范围：`/FlavorThresholdDB/aroma-threshold/` 检索页的新版结果展示

## 1. 背景与目标

现有检索页已经能够联合呈现阈值、FEMA、FlavorDB2、PubChem、书籍以及后续科研数据源，但结果区域按来源和记录纵向堆叠，身份信息重复，单条记录展开过多，页面越来越长。

本次重构将检索页改为“概览优先、章节导航、原始记录折叠”的科研档案工作台。目标是：

- 在一个视口内理解化合物身份、数据覆盖和关键证据；
- 将来源、介质和阈值类型筛选放回其所属章节；
- 保留每条科研记录的原始来源、条件、单位和证据状态；
- 单物质直接进入档案，批量任务先完成匹配审查；
- 新版默认启用，同时完整保留当前经典版；
- 不影响首页和岛津数据分析工作台。

## 2. 已确认的产品边界

### 2.1 本次包含

- 新版检索结果的信息架构与视觉层级；
- 单物质和批量匹配的结果行为；
- 章节内部筛选；
- 章节摘要与原始记录折叠；
- 加载、空结果、部分失败和整体失败状态；
- 新版与经典版切换；
- 桌面端和移动端适配；
- 既有导出功能在新版中的入口规划。

### 2.2 本次不包含

- 首页视觉重构；
- 岛津数据分析工作台改动；
- 外部数据源接口新增或后端数据规则修改；
- 经典版布局、配色、筛选方式和导出行为重构；
- 通过视觉聚合推导数据库未提供的科学结论。

## 3. 总体页面结构

新版检索页自上而下分为五层：

1. 现有平台导航与页面标题；
2. 精简检索模块；
3. 新版/经典版切换；
4. 化合物身份与数据覆盖概览；
5. 章节导航和章节内容。

新版顶部检索模块仅保留：

- 单物质检索 / 批量匹配；
- 中文名、英文名或 CAS 号输入；
- 精确 / 模糊匹配；
- 检索操作和必要帮助文字。

新版顶部不再显示 FEMA、FlavorDB2、PubChem、水、空气、其他介质、书籍、觉察阈和识别阈等全局按钮。这些条件进入相应章节。经典版继续显示现有全部筛选。

## 4. 化合物档案信息架构

新版结果划分为八个章节：

1. **档案概览**：首选名称、别名、CAS、PubChem CID、分子式、分类、身份匹配状态和章节覆盖；
2. **感官与天然来源**：FEMA、FlavorDB2、气味、味觉、天然来源、食材实体；
3. **阈值证据**：介质、阈值类型、数值、单位、实验条件、文献与书籍记录；
4. **谱图与鉴定**：MassBank、GNPS、EI、MS/MS、离子模式、仪器条件和谱图工具；
5. **生化关系**：Rhea 等反应、代谢或生化关系证据；
6. **活性与靶点**：PubChem BioAssay、ChEMBL 等活性记录；
7. **蛋白结构**：UniProt、PDB、AlphaFold 等蛋白与结构信息；
8. **引用与导出**：数据来源、引用示例、精简版与详细版导出。

### 4.1 分组原则

- CAS、CID、名称、分子式和分类只在身份区完整展示一次；
- FEMA 与 FlavorDB2 可并列比较，但来源标签不得合并或丢失；
- 阈值必须与介质、阈值类型、原始单位、实验条件和来源共同显示；
- 不提供脱离来源和条件的“唯一阈值”；
- 生化关系、活性/靶点和蛋白结构保持独立，避免把关联证据误写成因果机制；
- 每章默认显示摘要，完整原始记录按需展开；
- 谱图等重型工具仅在进入章节或主动展开时加载。

## 5. 导航与响应式布局

### 5.1 桌面端

- 左侧为粘性章节导航，右侧为当前章节内容；
- 当前章节高亮，并显示该章的记录数量或状态；
- 身份概览保持在章节内容上方，避免切换章节后失去对象上下文；
- 页面不同时渲染八章全部原始记录。

### 5.2 移动端

- 左侧导航转换为可横向滚动的章节选择器；
- 章节标题、记录数和筛选按钮允许自然换行；
- 记录从横向多列改为纵向阅读；
- 所有交互目标不小于 44 × 44 px；
- 不允许页面级横向溢出。

## 6. 章节内部筛选

筛选只影响已取得记录的显示，不改变化合物身份匹配。

### 6.1 筛选归属

- **感官与天然来源**：FEMA、FlavorDB2、气味、味觉、天然来源、食材实体；
- **阈值证据**：水、空气、酒类、其他介质、觉察阈、识别阈、书籍记录；
- **谱图与鉴定**：MassBank、GNPS、EI、MS/MS、正离子、负离子、仪器条件；
- **生化关系 / 活性与靶点 / 蛋白结构**：各章仅显示与本章相关的数据源和证据状态。

### 6.2 状态规则

- 各章节筛选状态互相独立；
- 离开章节后保留本次筛选；
- 发起新的化合物检索时恢复章节默认筛选；
- “全部”是明确状态，而不是空选状态；
- 筛选后无记录时显示“当前筛选下无记录”，不得显示为“该来源无数据”。

## 7. 单物质检索行为

单物质匹配成功后直接进入该化合物档案：

1. 首先展示身份概览和身份核验状态；
2. 默认进入“档案概览”；
3. 其他章节可并行获取数据并逐步变为可用；
4. 当前章节摘要先显示，原始记录默认折叠；
5. 新检索会重置章节选择和章节筛选，但保留新版/经典版偏好。

若存在多个候选身份，不直接拼接多个档案。应先显示候选列表，要求用户选择或明确采用最高可信匹配，并显示匹配依据。

## 8. 批量匹配行为

采用已确认的方案 A：“审查表格 → 单条档案”。

### 8.1 批量审查表格

每行代表一个输入项，至少包含：

- 原始输入；
- 标准化化合物名称；
- CAS；
- 匹配状态：精确、候选、未匹配或冲突；
- 数据覆盖：已覆盖章节或来源数量；
- 异常/缺失提示；
- 查看档案操作。

表格支持：

- 按匹配状态和覆盖程度筛选；
- 排序；
- 未匹配项优先审查；
- 复用既有批量导出能力；
- 点击一行进入与单物质完全相同的档案视图。

### 8.2 列表与档案切换

- 进入单条档案前保存表格筛选、排序、分页和滚动位置；
- 返回批量结果后恢复上述状态；
- 不同时展开多个完整档案；
- 不使用连续长卡片代替表格，以免重复当前页面过长的问题。

## 9. 新版与经典版切换

切换控件位于检索模块与结果内容之间。

- 新用户默认进入新版；
- 用户选择经典版后，在当前浏览器持久保存偏好；
- 切换只改变结果表现，不重新解释查询条件，不改变数据，不改变导出内容；
- 切换时保留当前检索输入和已经取得的结果；
- 经典版复用当前页面的布局、配色、筛选和导出逻辑，不做视觉重构；
- 偏好存储失败时静默回退到当前会话状态，不阻断检索。

## 10. 加载、空态与错误处理

### 10.1 渐进加载

- 化合物身份先返回并建立档案框架；
- 各章节独立加载；
- 已完成章节立即可读，不等待所有来源；
- 章节导航显示加载中、可用、部分可用或失败状态；
- 骨架屏只用于内容形状，不用闪烁动画干扰长时间阅读。

### 10.2 无结果

必须区分：

- 化合物身份未匹配；
- 当前章节没有来源记录；
- 当前筛选条件下没有记录；
- 数据尚未请求。

身份未匹配时保留输入，提供检查 CAS、使用英文名、切换精确/模糊或选择候选的恢复路径。

### 10.3 部分来源失败

- 成功数据继续展示；
- 明确列出失败或超时的数据源；
- 允许单独重试失败来源；
- 不因一个外部来源失败而清空整个档案；
- 导出时显式记录来源未取得状态，不能把失败伪装成空值。

### 10.4 整体失败

仅在身份检索或核心本地服务完全不可用时显示整页错误。保留输入、检索模式和视图偏好，并提供重新尝试。

## 11. 视觉系统

本页属于高密度科研产品界面，视觉优先级为可读性、层级和可信度，不追求营销页式动效。

### 11.1 色彩角色

- 页面底色：冷调浅灰蓝，用于降低长时间阅读疲劳；
- 内容面：白色；
- 一级文字：深墨蓝；
- 二级文字：中深蓝灰，正文和小字号均满足 WCAG AA；
- 主交互色：钴蓝，只用于当前导航、主按钮、选中筛选和焦点；
- 证据提示：克制琥珀色；
- 成功、失败颜色只表达状态，不用作数据源装饰。

禁止使用难以辨认的浅灰正文、渐变文字、大面积玻璃效果和无语义多彩标签。

### 11.2 排版与层级

- 化合物名称是结果区最高层级；
- CAS、CID 和英文名保持清晰但不与名称争抢；
- 章节标题、摘要、记录和来源形成稳定的四级层次；
- 正文行高适合中英文混排；
- 数据单位、证据状态和来源不得因字号过小而难以辨认。

### 11.3 动效

- 动效只用于章节切换、折叠展开和状态反馈；
- 只动画 `transform` 与 `opacity` 等低成本属性；
- 支持 `prefers-reduced-motion`；
- 不引入滚动叙事、视差或持续装饰动画。

## 12. 组件边界

实施时应从当前大型 `App.jsx` 中拆出独立、可测试的结果组件。建议边界：

- `SearchWorkbenchShell`：新版检索模块、版本切换和模式协调；
- `CompoundIdentityHeader`：身份和覆盖概览；
- `ChapterNavigation`：桌面侧栏和移动章节选择器；
- `ChapterPanel`：章节通用标题、状态、筛选和折叠框架；
- `ThresholdEvidenceChapter` 等领域章节组件：负责各自记录映射；
- `EvidenceRecordDisclosure`：摘要与原始记录展开；
- `BatchReviewTable`：批量匹配审查；
- `SourceStatusSummary`：来源加载和失败状态；
- `ResultViewSwitch`：新版/经典版偏好。

经典版继续由现有渲染路径负责。共享查询结果和导出数据模型，但不要求新旧视图共享展示组件。

## 13. 数据流原则

1. 现有查询逻辑生成标准化匹配结果；
2. 新版适配层把结果映射为身份、章节摘要、原始记录和来源状态；
3. 章节筛选仅作用于映射后的显示集合；
4. 经典版继续消费现有数据结构；
5. 导出使用既有标准化数据，不从屏幕 DOM 反向生成；
6. 每条记录保留可序列化的来源标识、原始单位、原始文本和必要的行/页证据；
7. 缺失、未请求和请求失败使用不同状态值。

新版适配层不得通过拼接文本制造新的科学事实，也不得丢弃经典版仍需要的字段。

## 14. 可访问性与交互要求

- 正文文字对比度至少 4.5:1，大字号至少 3:1；
- 所有筛选、章节、折叠和版本切换均支持键盘操作；
- 焦点状态清晰可见；
- 选中状态不能只依赖颜色；
- 折叠控件提供 `aria-expanded` 和关联内容标识；
- 加载和错误变化通过适度的 live region 通知，不重复播报每条记录；
- 中英文切换后不截断章节名称、按钮和状态文字。

## 15. 验收标准

### 15.1 功能

- 新版为默认结果视图，经典版可切换且完整保留；
- 新旧视图对同一查询使用相同的数据结果；
- 单物质直接进入档案；
- 批量检索先显示审查表格，进入并返回档案后恢复列表状态；
- 八个章节存在且字段归属正确；
- 章节筛选互相独立，新检索时重置；
- 原始记录默认折叠并可访问；
- 部分来源失败不影响成功内容；
- 现有精简版和详细版导出仍可用。

### 15.2 视觉与响应式

- 1440 px、1024 px、768 px 和 375 px 宽度下无页面级横向溢出；
- 移动端章节导航可操作，筛选和记录自然换行；
- 正文、标签、占位符和状态文字达到对比度要求；
- 长名称、长来源和长阈值文本不会覆盖操作控件；
- 首页和岛津工作台的视觉及行为没有变化。

### 15.3 回归与可靠性

- 精确/模糊、单物质/批量、中文/英文检索均有覆盖；
- FEMA、FlavorDB2、PubChem、书籍和阈值记录的来源信息未丢失；
- 新旧视图切换不触发重复外部请求；
- 重复 React key、控制台错误和未捕获 Promise 为零；
- 外部来源超时、返回空数组和返回部分字段均有测试；
- 版本偏好存储异常不阻断页面。

## 16. 实施顺序约束

为避免与正在进行的岛津数据分析接入发生冲突，正式实施应按以下顺序推进：

1. 先建立纯数据适配器和测试，不改岛津组件；
2. 创建新版结果组件目录，避免继续向 `App.jsx` 堆叠领域视图；
3. 接入单物质档案；
4. 接入章节筛选和状态；
5. 接入批量审查表格；
6. 接入新版/经典版切换；
7. 完成导出、响应式、无障碍和端到端回归；
8. 验证首页与岛津工作台无变化后再交付。

实施计划必须以当前工作树为基线，保留并避开岛津相关未提交文件，不得通过重置或覆盖来消除冲突。

## 17. 设计决策摘要

- 首页保持现状；
- FlavorThresholdDB 与岛津分析平台并列归入 HXQLab，各自拥有独立工作台；
- 岛津分析平台保持现状；
- 检索页采用概览优先的档案布局，吸收章节折叠；
- 顶部保留精简检索，筛选进入章节内部；
- 新版默认、经典版完整保留；
- 批量结果采用方案 A：审查表格后进入单条档案；
- 部分失败保留成功数据并支持来源级重试；
- 视觉采用高对比、冷调、克制的科研工作台体系。
