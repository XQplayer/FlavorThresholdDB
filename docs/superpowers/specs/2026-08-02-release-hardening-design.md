# FlavorThresholdDB 全面优化与发布治理设计

日期：2026-08-02  
状态：待用户审核  
范围：当前 `codex/pubchem-volatile-properties` 工作树中的 PubChem PUG View、FlavorDB2 与既有检索页面

## 1. 目标

在不改变阈值、书籍索引和来源追溯语义的前提下，把当前本地功能整理为可验证、可重复启动、可安全发布的版本。此次工作处理审计中已经确认的缓存准确性、前端依赖安全、重复服务、运行产物污染、页面遮挡、首屏负载和文档漂移问题。

完成标准：

- PubChem 解析规则升级后不会继续返回旧解析缓存；
- 前端不再包含 `xlsx` 及 Excel 上传入口；
- 本地前端固定使用 `127.0.0.1:5174`，代理固定使用 `127.0.0.1:8787`，重复启动不会产生第二套服务；
- Playwright、Superpowers 和运行时缓存不会混入功能提交；
- RDKit 与 3Dmol 仅在用户进入相关结构视图时加载；
- 固定底栏不遮挡任何页面内容；
- 项目历史、数据来源、变更记录和测试基线与当前实现一致；
- 全部自动化测试、构建、依赖审计和桌面/移动端实测通过。

## 2. 非目标

- 不重写阈值数据库或书籍索引；
- 不改变当前精确与模糊检索语义；
- 不拆分整个 `App.jsx` 或重构全站 CSS；
- 不新增 Excel 替代导入格式；
- 不在本阶段合并 `main`、推送 GitHub 或触发公网部署。

## 3. 变更设计

### 3.1 PubChem 缓存契约

为 PubChem 挥发与分配性质缓存增加显式缓存元数据：`schema_version`、`parser_version`、`retrieved_at`。读取缓存时同时检查版本和 TTL；任一不满足即视为未命中并重新请求。仅成功且结构完整的结果可持久化，临时网络错误继续保持非缓存状态。

缓存文件仍使用原子替换与现有锁机制。实现不依赖手工删除整个缓存文件，也不影响 FEMA、旧 FlavorDB 或 FlavorDB2 的现有命名空间。当前旧格式 `pubchem-volatile:*` 条目会在首次访问时自然更新。

默认 TTL 采用 30 天。解析器版本是科学语义变更的主要失效条件，TTL 用于避免上游实验属性长期不刷新。

### 3.2 暂停 Excel 导入

移除页面中的 Excel 文件输入、`FileReader` 解析流程、`XLSX.read` 调用以及 `xlsx` 生产依赖。相关按钮与说明同步移除，不保留不可用的灰色入口。CSV 导出和现有检索能力不受影响。

完成后生产依赖审计不得再报告当前两个 SheetJS 高危漏洞。

### 3.3 单实例后台启动

统一正式本地开发入口：

- 前端：`127.0.0.1:5174`；
- 数据代理：`127.0.0.1:8787`；
- 启动前检查端口和进程命令行；
- 发现本项目现有实例时复用并验证，不重复启动；
- 发现端口由其他程序占用时明确失败，不自动杀死未知进程；
- 所有新进程隐藏窗口运行；
- 启动完成后验证页面、`/health` 和核心外部数据接口；
- 提供只停止本项目已确认进程的配套停止脚本。

`start_local.cmd` 保留为兼容入口，但委托 PowerShell 脚本完成实际进程管理。PID 文件属于运行产物并被忽略。

### 3.4 仓库与缓存卫生

`.playwright-cli/`、`.superpowers/`、PID、日志和临时验证结果加入忽略规则。可长期复用的端到端测试迁移到正式测试目录，避免依赖个人临时目录结构。

`fema_flavor_cache.json` 不作为本次功能代码提交的一部分。缓存若继续保留在仓库中，只能作为明确的预热快照单独生成、审核和提交；普通运行产生的变化不得混入发布提交。

### 3.5 前端性能与布局

RDKit 和 3Dmol 改为动态导入：初始检索页面不下载大型结构解析与三维渲染模块；用户选择对应结构视图后再加载，并显示轻量加载状态。加载失败只影响结构视图，不影响化合物身份、阈值、书籍和来源信息。

页面主体增加与固定底栏相匹配的安全底部空间，并在移动端使用安全区变量，保证最后一张卡片和展开内容不会被覆盖。不改动现有视觉主题和卡片信息层级。

## 4. 测试策略

行为变更遵循测试先行：

1. 缓存测试先证明旧版本、过期版本和缺少元数据的条目会失败，再实现版本与 TTL 判断；
2. 前端静态测试先证明 Excel 入口和 `xlsx` 依赖仍存在，再移除实现；
3. 动态加载测试先证明大型模块仍位于初始入口，再改成懒加载；
4. 启动脚本测试覆盖固定端口、重复启动、陌生进程占用和健康检查；
5. 布局 E2E 检查页面最后内容与底栏边界，不只检查水平溢出。

最终验证矩阵：

- Python 代理测试；
- 书籍索引 60 项管线测试和质量门槛；
- 全部前端 Node 测试；
- ESLint；
- Vite 生产构建及静态路由；
- `pnpm audit --prod`；
- `git diff --check`；
- 桌面端和移动端 Playwright；
- FEMA、FlavorDB2、PubChem、书籍检索及外部服务失败隔离实测。

## 5. 风险与回退

- 动态导入可能暴露第三方库对浏览器环境的隐式依赖，因此每个结构视图保留独立错误边界；
- 首次访问旧 PubChem 缓存会产生一次上游请求，现有每秒五次限流继续生效；
- 单实例脚本只管理命令行路径确认属于本项目的进程，避免误杀其他开发服务；
- Excel 暂停属于明确产品变更，恢复时必须选用维护中的安全解析方案并重新设计上传边界；
- 所有实现保留在当前功能分支，完成验收前不合并 `main`，可通过当前 HEAD 或发布备份回退。
